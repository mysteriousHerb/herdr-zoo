# herdr-zoo

Personal layouts and mods for the **Herdr** desktop app (terminals + coding agents), built
for fun: the user's agents shown as animated creatures (Kenney's CC0 3D packs Cube Pets,
Blocky and Mini Characters, pre-rendered to GIFs). Read Herdr's own manual first —
`~/.config/herdr-app/AGENTS.md` (rewritten by Herdr on every start) and the API types
next to it, `herdr.d.ts` and `gpui-kit.d.ts`. They are the truth; this file is only
what we built on top.

## How this repo relates to Herdr

Herdr only reads `~/.config/herdr-app/`. This repo is the source; `sh scripts/deploy.sh`
copies `layouts/` and `mods/` there (copy only, never deletes) and runs
`herdr-app check` on each mod. A layout is copied only when the repo's copy changed since the
last deploy (`layouts/.deployed/` there): Herdr rewrites the deployed `zoo.json` itself (the quick
terminal's `layout.set`), and a changed repo copy still overwrites that, dragged sizes included. Herdr hot-reloads within a second. Herdr writes its files
with CRLF; the repo is LF (`.gitattributes`), so strip `\r` when copying anything back.

Not in the repo, on purpose: `settings.json` (Herdr and the zoo's ♪ dialog both write it),
`keys.json`, and the user's own `layouts/my-layout.json` (a `main` clone using `my-tabs`).

- After any mod edit: deploy, then `herdr-app status` (its `errors` must be empty) and
  `herdr-app shot <file.png>` to look at the window. Never call a mod done without a
  passing check.
- Shipped Herdr layouts/mods are read-only; we clone (`mod.clone`, `layout.clone`) and edit clones.
- **A Herdr update can rewrite the deployed layout**: on 2026-11-06 the first start of 0.1.13 rewrote
  `~/.config/herdr-app/layouts/zoo.json` (the active layout) 3 s after start, without the `panel` column
  (so the Files/Changes button couldn't hide the panel), the root `colors` and `titlebar`. Not seen in
  the repo. After an update, `diff` the deployed layout against the repo's and redeploy.
- A mod cannot import from another mod's folder (`../zoo/x.js` fails the check), hence
  the duplicated `sprites.js` (written by `make_packs.py`) in `zoo`, `zoo-agents` and `my-tabs`,
  and `volume.js` in `zoo` and `zoo-agents`.
- **Clicking from the CLI**: `scripts/mouse.ps1` sends mouse messages to the Herdr window (no real cursor
  move), then `herdr-app shot` to see the result. Coordinates are the window's client pixels, which
  are `herdr-app shot` pixels only at 100% display scale: the script prints `client WxH`, and at
  125% (1520x807 client, 1900x1009 shot; seen 2026-11-02) divide shot pixels by 1.25. Check an
  overlay opened with `herdr-app status` (`overlays`): the shot didn't draw the ♪ dialog that time.
  Older notes saying "no CLI click" predate the script.
- **Keys from the CLI**: `scripts/keys.ps1 -plan "ctrl v; wait 200; enter"` posts key presses to the
  Herdr window, which needn't be in front (modifiers go into Herdr's keyboard state via
  `AttachThreadInput`). They land wherever Herdr's keyboard focus is, like real keys. **Ask the user
  first** and test in a scratch tab: on 2026-11-02 the user switched tabs mid-test and a Ctrl+A/Ctrl+X
  cut their half-typed chat message. That test found the chat already handles Ctrl+V (paste into the
  box), Ctrl+A/Ctrl+X in the box and Ctrl+C on a dragged message selection, so it needs no
  Ctrl+Shift (that's only for terminals).
- On Windows there is no bare `python`; run scripts with `uv run scripts/<x>.py` (PEP 723 deps).
- **Speed** (measured 2026-10-30): mods run on Herdr's UI thread, so a slow script stalls the
  whole window. After ~50 min of deploys and layout switches the window held a core at 100% even
  on the stock `main` layout with our mods idle; a restart (`herdr-app do app.quit`, relaunch)
  brought it to 10–20%. Restart Herdr after a burst of deploys. Runtime limits found: `fs/promises`
  has only `readFile`/`readdir`/`exists`/`writeFile`/`mkdir`/`rmdir`/`unlink` (no `open`/`stat`);
  `readFile(path)` with no encoding gives bytes (25 ms for 11 MB vs 60–150 ms as utf8), but
  `writeFile(path, Uint8Array)` resolves and leaves an **empty file** (0.1.10; base64 text + a
  shell decode instead, `writeBytes` in `zoo/volume.js`); `Buffer`
  can't decode bytes and there's no `TextDecoder` (`decodeURIComponent(escape(binary))` works);
  `gpui-fps` throws. A minimized window doesn't paint, so `herdr-app shot` returns an old frame. Herdr caches images by path, including a miss: changing an image means a new file name, and a new file must be in `~/.config/herdr-app` before the code that names it is (a deploy copies mods one by one, so a mod can reload and ask before the file lands; that left blank icons on 2026-11-01).

  `mods/zoo/packs/<pack>.json` = `{id, name, credit, files: {work, blocked, done, idle}` (paths

  (persisted in `~/.config/herdr-app/shared.json`; the old `zoo.dex` numbers are no longer read,

  starting from a hash of its address, among the packs in shared `zoo.packs` (default: only

- **Unread vs done** (2026-11-02, agents list and tabs only): Herdr's `done` means unread
  (finished while you weren't looking) and turns `idle` once you look, so a read agent looked
  like a fresh one. Worse, Herdr only counts looking at the terminal: with the Chat view in front
  an agent stays `done` while you read it (seen: the focused `t32` was `done` in `hc ls`, and there's
  no command to mark it seen). So shared `zoo.turns` = `{ "<address>": "run" | "seen" }`
  (`trackTurns`, in `zoo-agents` and `my-tabs`, kept in step): `run` while working/blocked, `seen`
  when it is `done` and `focused().agent` with `window().active`. Shown (`shownStatus`): **unread**
  = Herdr's done not yet seen (accent dot; the character keeps its done nod), **done** = seen, or
  idle after any turn (gray ✓; idle animation), **idle** = no turn yet (ring). Priority sections:
  Needs you > Unread > Working > Done > Idle; an unread agent you open stays in Unread until you
  leave it (`hold`). Seen by screenshot. Not changed: the zoo strip (`zoo-top`), the board, the
  sounds and Herdr's own spaces dots still go by Herdr's `done`.
- **Sounds**: shared state `zoo.sounds` = `{ blocked, done }`, each `chime` | `silent` |
  `file:<name>.mp3` (an old saved `cry` reads as `chime`). **Herdr 0.1.9 ignores `settings.json` `sounds.done`/`blocked`**
  (always its chime; verified 2026-10-30 by recording system audio with a WASAPI loopback,
  `soundcard` package). So the zoo plays every choice itself (`playSound`) on a status
  transition, **Zoo layout only**, and choosing sets `sounds.enabled: false` so Herdr doesn't
  chime too. `playSound(file)` from a mod still plays with `enabled: false`; corner notes still
  show. Choosing still writes `sounds.<event>` (file = `mods/zoo/sounds/<f>`, silent =
  `mods/zoo/silent.mp3`, chime = key removed) for when Herdr honors it. Once fixed: drop
  `enabled: false` and let Herdr play them. Current choice: done = `ping`,
  blocked = `two-tone`.
- **Volume**: shared `zoo.volume` = `{ blocked, done }`, 0–100 (default 100), a slider at the top
  of each column of the ♪ dialog (letting go saves and plays it). `playSound` has no volume, so
  `mods/zoo/volume.js` plays a quieter copy: the same MP3 with every frame's `global_gain` lowered
  (1.5 dB a step, like mp3gain; loudness = slider², so 50% = −12 dB), in `data/zoo/volume/`
  named `<steps>-<source size>-<path>` (kept across runs, never rewritten). Writing bytes needs a
  PowerShell call (~0.8 s), so copies are made **ahead**, many per call (`prepare`): the dialog
  makes every slider level (5% steps) of the chosen sounds when it opens or a sound is picked,
  and the zoo makes each agent's sound at the set level, so letting go and alerts play at once.
  These tasks use `{ owner: null }` and time out after 10 s (`cx.sleep`; there's no
  `setTimeout`): a reload ends a build's tasks mid-way. The slider's knob needs `mt(-4)` (the
  shell places it from the left only), and the % redraws only when it changes. Verified
  2026-10-31: the copies decode and measure exactly −12.04 dB at 50%, for 22 kHz mono (MPEG-2,
  the cries and `sounds/`) and 44.1 kHz stereo (MPEG-1); knob seen on the bar. Herdr's chime
  can't be scaled (its slider is grayed).
